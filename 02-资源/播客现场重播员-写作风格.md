# 播客现场重播员 — 写作风格指南

> 典型场景：将英文播客/访谈视频转写为中文深度笔记式长文
> 参考文章：《设计流程已死：Anthropic 设计负责人 Jenny Wen 谈 AI 时代的设计变革》、《Peter Steinberger 访谈》

---

## 【一】一句话风格画像

**技术圈深度访谈的"现场重播员"：用对话流推进叙事，用短句制造节奏，用加粗锚定关键信息，用中英对照金句还原现场感，让读者像听播客一样读完长文。**

---

## 【二】文章结构模板

```
1. 嘉宾身份卡片（2-3句交代 Who / 现在做什么 / 之前做什么，关键经历加粗）
2. 本期概要（5-6个要点，无序列表 + 加粗关键词，每条一句话）
3. 正文分段（按播客话题拆 5-8 个独立章节，每章节一个 ## 标题）
4. 闪电问答（如有，单独一节，快节奏呈现）
5. 作者总结（1-3段个人观察，指出"值得关注的信号"和"未解的问题"）
6. 原始视频链接
```

---

## 【三】核心逻辑规则

**规则1：标题采用"核心观点 + 人物身份 + 话题范围"结构**
大标题必须有冲击力，包含最反直觉的观点。例："设计流程已死：Anthropic 设计负责人 Jenny Wen 谈 AI 时代的设计变革"

**规则2：章节标题用完整陈述句，带观点或判断**
例："设计流程已死，不是自己死的，是被工程速度'逼死'的"、"构建软件最难的部分，不是构建它"。标题本身就是这一节的核心论点。

**规则3：开篇前3段完成"嘉宾身份 + 播客来源 + 核心话题预告"**
第一段用2-3句交代嘉宾背景（现职 + 前职 + 代表作品），关键信息加粗。第二段交代播客来源和话题列表。

**规则4：段落长度控制在2-5句**
避免超长段落。遇到复杂论述时，通过引用块、列表或换段拆分。

**规则5：叙事推进采用"对话流 + 第三人称转述"**
通过"Jenny 说""Lenny 追问""她指的是..."等对话标记推进内容。适度加入说话者情绪描写："很直接""笑着说""她纠正了这个印象"。

**规则6：核心金句用中英对照引用块**
中文翻译在前，英文原文括号在后，均放在 blockquote 内：

```markdown
> 设计师们被教导的那套设计流程，我们曾经把它当圣经一样遵循，现在基本已经死了。
> （"This design process that designers have been taught—we sort of treat it as gospel—that's basically dead."）
```

一篇文章约 5-8 处原文引用，只挑有冲击力的金句。

**规则7：术语和人物用【注：...】标注**
首次出现的专业术语、人名、背景信息，用独立一段的【注：...】解释：

```markdown
【注：Boris Cherny 是 Claude Code 的创建者和负责人，在 2026 年 2 月的 Lenny's Podcast 中表示"编码这件事基本已经被解决了"。】
```

**规则8：数字信息精确引用 + 对比呈现**
所有涉及数据的信息保留原始数字，用列表做前后对比：

```markdown
- **几年前**：60-70% 做设计稿和原型，20% 和工程师配合，10% 开协调会
- **现在**：30-40% 做设计稿和原型，30-40% 和工程师直接配合，还多了一块——自己写代码实现
```

**规则9：口语化连接词推进段落**
使用"关于这一点""鉴于""有一次""问题是"等词制造即时感。避免"首先""其次""综上所述"等书面逻辑词。

**规则10：加粗用于关键概念、人名、产品名首次出现**
例："__双钻石模型__""__Claude Co-work__""__IC__（Individual Contributor，个人贡献者）"。首次出现时中文 + 英文全称，后续不重复解释。

**规则11：列表用于并列概念和枚举**
三种设计师类型、工具栈列举、多个要点等场景使用无序列表。列表项以加粗关键词开头，后接简短说明。

**规则12：结尾指出信号和未解问题，不做全文总结**
不复述前文内容，而是提出 1-2 个值得关注的信号或未解问题。可以带一点个人判断，但点到为止。最后附原始视频链接。

## 【四】语言与视觉元素清单

### 高频词汇/句式特征

- **对话标记**："问""说""回答""追问""笑着说""很直接""纠正了这个印象"
- **时间锚点词**："有一次""第一次""现在""后来""当时""过去一年"
- **转折连接词**："问题是""但她指出了一个更根本的问题""关于这一点""鉴于"
- **口语化句式**："这个数字在网上传得很广""这种人很稀有""听起来像认命"
- **元叙事句式**："Lenny 把这总结为...""Jenny 把这个框架用在了..."

### 视觉排版规范

- **段落密度**：每段 2-5 句，避免超长段落
- **引用块**：每个核心章节至少 1 个中英对照引用块
- **加粗频率**：平均每 2-3 段出现加粗，用于人名、概念、核心论点
- **列表使用**：正文中用于并列概念、数据对比、要点枚举
- **章节标题**：## + 完整陈述句，有画面感和观点
- **注释格式**：【注：...】独立成段，紧跟相关内容之后
- **图片**：每个主要章节配一张信息图/示意图，紧跟相关论述

---

## 【五】风格红线

**红线1：不逐字翻译，不做字幕式排版**
是"重播"不是"翻译"，要有重新组织和取舍。

**红线2：不加"以下是播客摘要"等元描述**
直接进入内容，不做价值预判。

**红线3：不使用"非常""十分""极其""令人震惊"等程度副词和主观评价**
所有强调通过具体数字、引用块、加粗实现。

**红线4：正文中不频繁插入个人评价**
作者观点集中放在结尾总结段，正文保持"重播员"的客观转述角色。

**红线5：不用 emoji**

**红线6：不用"让我们来看看..."、"接下来我们聊聊..."等过渡套话**

---

## 【六】风格本质

这是一种**"播客式长文阅读"**的写法——用第三人称对话流作为叙事骨架，用中英对照金句还原现场感，用加粗+引用块+【注：】三层标注系统锚定关键信息，把一场 60-90 分钟的英文播客转化为"读完等于听完精华"的阅读体验。

核心能力在于**取舍和重组**：不是忠实翻译全文，而是判断哪些话值得原文引用、哪些概念需要注释、哪些段落可以合并压缩，最终产出一份比原始播客更高效的信息载体。
